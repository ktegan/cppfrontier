# Upstream Logic Audit

This document compares the implemented compiler pipeline with upstream cppfront
`source/to_cpp1.h`, its Cpp2 documentation, and its regression-test oracle
outputs. `ARCHITECTURE.md` remains authoritative for the supported capability
set; this file records the audit evidence, deliberate approximations, and open
compatibility questions.

Upstream reference used for this audit:

- checkout: `../cppfront`
- commit: `66eb614`
- documentation: `docs/cpp2`
- oracle output: `regression-tests/test-results`

## Status vocabulary

- **Match**: the local implementation produces the same Cpp1 semantics and
  has a focused test.
- **Approximation**: the local output is simpler than upstream but preserves
  the documented behavior.
- **Gap**: the behavior is not implemented. The limitation is stated in
  `ARCHITECTURE.md` and is not claimed as supported.
- **Upstream question**: upstream behavior is unclear, incomplete, or known to
  have issue history; the local implementation does not silently guess.

Each `@autodiff` runs before other reflection, in program order, so a second `@autodiff` on a type also differentiates the first one's output. The file includes `"cpp2taylor.h"` or `"cpp2ad_stack.h"` when a mode needs them. Upstream's limitations and messages are kept: no reverse `while`/`do`, compound assignments, overloads, or nested member calls, and special functions are `sin`, `cos`, `exp`, `sqrt`, and `push_back`. Unlike upstream, reverse mode also diagnoses `for` loops, member access such as `t.a`, `break`, `continue`, prefix operators, and a `return` before the end of the function, and handles `if`: the primal pass pushes the branch taken on the ad stack and the backprop pass pops it. A literal has no backprop statement and a copy `r = x` propagates `x_b += r_b`, where upstream generates invalid code; a deduced local's adjoint has the active scalar type, and passive locals are declared in the reverse derivative. Assigning a variable that holds a value (a parameter, an initialized local, or one assigned before) or that the right side reads saves its old value for the backprop pass, which restores it, where upstream saves only a self-reading assignment inside a block; a block saves every variable assigned in it, and the returned values are kept aside while the backprop pass restores them. In forward mode a `for` loop over a passive range, such as a `std::vector<int>` or `(0 ..< n)`, iterates only the range, and a passive variable has a zero derivative (`r = n` gives `r_d = ()`), where upstream names a missing `idx_d` or `n_d`; a `return` before the end of the function returns, where upstream continues, and a function with an unnamed return cannot declare `r`, the name of its differentiated return value. Unlike upstream, `rws_suffix=` sets the reverse suffix (upstream sets the forward one). A function or type that has, or whose type has, an `@autodiff` with the same arguments is not differentiated again when another `@autodiff` declaration calls it (upstream generates its derivative a second time). An `@autodiff` type in a namespace is differentiated once, where upstream also reads its members' derivatives from the type itself; a call of a member function on `this`, such as `scaled(x)` in a member function, passes `this_d` (upstream omits it); reverse mode diagnoses member functions, whose `T_b` type it does not generate (upstream emits code naming it). After an `AD:` error the generated code is not parsed, so no second error dumps it. Generated temporaries `temp_<n>` skip the numbers that begin a parameter, return or local name of the function, so a second `@autodiff<"suffix=_d2">` can differentiate `f_d` (upstream declares its `temp_1` twice). A function with a deduced return type, such as `-> _`, is diagnosed, since a derivative returns named values, which need a type (upstream generates `-> (r, r_d)` and rejects it); a declared `-> forward T` is differentiated as `-> T`, as upstream. A function template is diagnosed (upstream drops its template parameters and rejects the generated code). The backprop pass resets the adjoint of an initialized local after its initializer's backprop, as it does for an assignment, so passing it to a reverse call such as `g_b(y, y_b, a, a_b, b_b)` for `b := g(y, a)` is not its last use, which would move it. Reverse mode with `order=` greater than 1 is an alpha limitation, where upstream generates Taylor tangents and adjoints of different orders, and reverse mode diagnoses a call of `push_back`, where upstream emits `TODO` into the code. A function without a return value, such as one that updates an `inout` parameter, has a derivative without a return value (upstream generates `-> ()` and rejects it); reverse mode diagnoses a call of one as a statement, since its backprop call would need the arguments as they were before the call. Diagnostics inside a derivative point at the function it was generated from, and generated text whose statements are not single expressions (such as `r_d = ;`, where upstream's parse fails) is rejected.
